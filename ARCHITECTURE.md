# 1. Introduction

AegisSOC is an on-premises Security Operations Intelligence Platform designed to improve cyber defence capabilities for BFSI organizations.

The platform focuses on:

- MITRE ATT&CK-based detection coverage
- Guided threat hunting
- SOC maturity assessment
- Detection gap analysis
- AI-assisted security investigation

AegisSOC is designed with a security-first architecture where organizational security data remains inside the organization's controlled network environment.

---

# 2. Architecture Principles

AegisSOC follows the following principles:

## 2.1 Security First

Security controls are integrated into every layer.

Examples:

- Authentication
- Authorization
- Audit logging
- Secure coding practices
- Data protection

---

## 2.2 On-Premises First

The platform is designed to operate without mandatory external cloud dependencies.

Security telemetry remains inside the organization.

External communication is optional and controlled.

---

## 2.3 Modular Design

AegisSOC uses a modular monolith architecture in version 1.0.

Each capability is developed as an independent logical module.

Benefits:

- Easier maintenance
- Better testing
- Clear ownership
- Future scalability

---

## 2.4 Explainable Security Decisions

Security recommendations generated by AI must provide:

- Reasoning
- Evidence
- Confidence level
- Supporting data

AI assists analysts and does not replace human decision making.

# 4. Core Modules

## 4.1 Identity and Access Management

Purpose:

Provide secure access control.

Responsibilities:

- User authentication
- Role management
- Permission management
- Session control
- Audit tracking

---

## 4.2 Asset Inventory Module

Purpose:

Maintain visibility of organizational assets.

Supported assets:

- Servers
- Endpoints
- Network devices
- Applications
- Cloud resources

---

## 4.3 Event Ingestion Module

Purpose:

Collect security telemetry.

Sources:

- Windows Event Logs
- Linux Syslog
- Sysmon
- Firewall
- WAF
- EDR
- VPN
- DNS
- Vulnerability scanners

---

## 4.4 Event Normalization Module

Purpose:

Convert different log formats into a common AegisSOC event format.

Example normalized fields:

- Timestamp
- Host
- User
- Process
- Network information
- Event category
- Severity

---

## 4.5 MITRE ATT&CK Engine

Purpose:

Map security events and detections to ATT&CK techniques.

Capabilities:

- Technique mapping
- Sub-technique mapping
- Coverage analysis
- Detection visibility analysis
- ATT&CK heatmap generation

---

## 4.6 Detection Engineering Module

Responsibilities:

- Detection rule management
- Sigma rule support
- Rule validation
- Detection improvement recommendations

---

## 4.7 Threat Hunting Engine

Purpose:

Enable proactive threat hunting.

Capabilities:

- IOC hunting
- Behaviour-based hunting
- ATT&CK-based hunting
- Scheduled hunting
- AI-assisted hunting

---

## 4.8 Correlation Engine

Purpose:

Connect multiple security events.

Example:

Authentication event

+

PowerShell execution

+

Network connection

=

Potential attack chain

---

## 4.9 Case Management Module

Responsibilities:

- Incident tracking
- Evidence management
- Investigation timeline
- Analyst collaboration

---
